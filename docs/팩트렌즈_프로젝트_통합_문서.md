# 팩트렌즈 프로젝트 통합 문서

이 문서는 FactLens 프로젝트의 현재 `main` 기준 상태, Git 병합 과정, 역할별 체크리스트, 사용하는 AWS 기술과 개발 도구, 그리고 각 도구가 어떻게 연결되어 작동하는지 정리한 팀 공유 문서다.

## 1. 프로젝트 정의

FactLens는 AWS/AI 발표자료나 보고서의 텍스트를 입력받아 핵심 주장 문장을 추출하고, AWS 공식 근거 문서 또는 fallback 근거 데이터와 비교해 문장별 신뢰 상태를 판정하는 RAG 기반 검증 서비스다.

판정 라벨은 아래 4개로 고정한다.

```text
근거 있음
공식 근거와 충돌
근거 부족
과장 표현
```

MVP 데모 흐름은 다음과 같다.

```text
텍스트 입력
→ claim 추출
→ AWS 공식 근거 검색 또는 fallback evidence 검색
→ RAG/Bedrock 판정
→ DynamoDB 저장
→ React 화면 표시
```

현재 MVP는 텍스트 입력을 기준으로 검증한다. PDF 업로드, PPTX 직접 분석, Guardrails 고도화는 확장 기능이다. 실시간 공식 출처 인터넷 검색은 `searchMode: "internet"` 옵션과 검색 API 키를 통해 사용할 수 있도록 구현했다.

## 2. Git 병합 기록

작업 브랜치는 역할별로 분리했다.

| 역할 | 브랜치 | 상태 |
|---|---|---|
| RAG & Bedrock | `feature/rag-bedrock` | `main` 병합 완료 |
| Backend & AWS API | `feature/backend-api` | `main` 병합 완료 |
| Frontend & UX | `feature/frontend-ui` | React MVP 구현 완료, `main` 병합 완료 |
| Data, Demo & Presentation | `feature/demo-docs` | 별도 문서/데모 브랜치로 관리, 최신 `main` 병합 필요 |

실제 병합 순서:

```bash
git checkout main
git merge --ff-only origin/main
git merge --no-edit origin/feature/backend-api
git merge --no-edit origin/feature/rag-bedrock
git push origin main
```

병합 중 충돌이 발생한 파일:

```text
backend/README.md
docs/api-contract.md
infra/README.md
sample-data/evidence_docs.json
sample-data/sample_wrong_aws_deck.md
sample-data/README.md
```

충돌 해결 기준:

- 백엔드 API 계약과 SAM 배포 구조는 `feature/backend-api` 기준을 우선했다.
- RAG 실행에 필요한 `backend/rag/*`, `docs/rag-prompts/*`, `sample-data/evidence_docs.json` 배열 구조는 `feature/rag-bedrock` 기준을 유지했다.
- 데모 입력은 백엔드 smoke용 `sample-data/sample_wrong_aws_deck.md`와 RAG 데모용 `sample-data/demo-inputs/sample_wrong_aws_deck.md`를 함께 유지했다.
- 잘못 생성된 S3 버킷 `factlens-rag-evidence-069423016509-ap-northeast-2`는 사용하지 않고, `factlens-dev-evidence-docs-069423016509-ap-northeast-2`만 사용하도록 문서화했다.

현재 `main` 기준 커밋:

```text
f0db778 feat: add official source internet search mode
738e1c1 chore: deploy backend api and document endpoint
23c60a7 docs: add project integration guide
7964387 Merge remote-tracking branch 'origin/feature/rag-bedrock'
8d0098f Merge remote-tracking branch 'origin/feature/backend-api'
5478552 chore: align project structure with team checklist
```

팀원이 최신 main을 받는 명령어:

```bash
git checkout main
git pull origin main
```

## 5. 프로젝트에 사용되는 AWS 기술

### 5.1 Amazon S3

용도:

- 사용자가 업로드한 PDF/텍스트 원본 저장
- Knowledge Base에 넣을 공식 근거 문서 저장
- fallback evidence JSON 백업 저장
- 분석 요청 원문 텍스트 archive 저장
- 프론트엔드 정적 호스팅 후보

현재 근거 문서 버킷:

```text
factlens-dev-evidence-docs-069423016509-ap-northeast-2
```

현재 S3 객체:

```text
s3://factlens-dev-evidence-docs-069423016509-ap-northeast-2/source-docs/aws-evidence-corpus.md
s3://factlens-dev-evidence-docs-069423016509-ap-northeast-2/fallback/evidence_docs.json
```

입력 archive 버킷:

```text
factlens-input-archive-dev-069423016509-ap-northeast-2
```

이 버킷은 `InputArchiveBucket` CloudFormation 리소스로 생성 완료됐고, `POST /analyze` smoke test에서 원문 텍스트 저장을 확인했다.

### 5.2 AWS Lambda

용도:

- API 요청 처리
- 입력 텍스트 validation
- RAG 분석 함수 호출
- 분석 결과 정규화
- DynamoDB 저장

현재 백엔드 엔트리포인트:

```text
backend/src/app.mjs
```

RAG 엔트리포인트:

```text
backend/rag/lambdaHandler.mjs
```

### 5.3 Amazon API Gateway

용도:

- 프론트엔드와 Lambda 사이의 HTTP API 제공
- `POST /analyze` 요청 수신
- `GET /analyses/{analysisId}` 조회 제공
- CORS 처리

현재 API는 CloudFormation stack `factlens-backend-api`로 배포되어 있고, base URL은 CloudFormation Outputs의 `ApiEndpoint`에서 확인한다.

```text
https://kprxxco5hi.execute-api.ap-northeast-2.amazonaws.com
```

### 5.4 Amazon DynamoDB

용도:

- 분석 결과 저장
- `analysisId` 기준 조회
- summary와 claims 저장

최소 저장 필드:

```text
analysisId
status
summary
claims
createdAt
```

### 5.5 Amazon Bedrock

용도:

- claim 추출, 근거 대조, 판정 설명, 수정 문장 생성을 담당할 LLM 실행
- 현재 MVP에서는 Bedrock 연결 지연에 대비해 deterministic fallback judge를 사용한다.

Bedrock 판정 입력 개념:

```text
claim 문장
+ 검색된 evidence
+ 고정 라벨 규칙
→ label, confidence, reason, correctedText, sources
```

### 5.6 Bedrock Knowledge Bases

용도:

- S3에 저장된 공식 근거 문서를 인덱싱
- claim별 관련 근거 검색
- RAG 기반으로 Bedrock 판정의 근거 제공

현재 MVP 상태:

```text
S3 근거 문서 준비: 완료
fallback evidence 검색: 완료
Knowledge Base 생성: 남은 작업
Data Source sync job: 남은 작업
```

### 5.7 AWS IAM

용도:

- Lambda가 DynamoDB에 읽기/쓰기를 할 수 있게 권한 부여
- Lambda가 S3 근거 문서를 읽을 수 있게 권한 부여
- Lambda가 입력 archive S3 버킷에 원문 텍스트를 쓸 수 있게 권한 부여
- 필요 시 Lambda가 Bedrock Runtime 또는 Knowledge Bases API를 호출할 수 있게 권한 부여

### 5.9 인터넷 검색 API

용도:

- claim별로 최신 공식 출처 후보를 찾는다.
- 검색 결과 중 `docs.aws.amazon.com`, `aws.amazon.com`, `repost.aws` 도메인만 evidence로 사용한다.
- 검색 API 키가 없거나 검색 실패 시 기존 fallback evidence로 자동 전환한다.

지원 provider:

```text
Brave Search API
SerpAPI
Google Programmable Search Engine
```

요청 예시:

```json
{
  "documentText": "AWS Lambda 함수는 최대 5분까지만 실행할 수 있다.",
  "maxClaims": 3,
  "searchMode": "internet"
}
```

필요 환경변수:

```text
FACTLENS_SEARCH_MODE=fallback
FACTLENS_SEARCH_PROVIDER=auto
FACTLENS_ALLOWED_SOURCE_DOMAINS=docs.aws.amazon.com,aws.amazon.com,repost.aws
FACTLENS_SEARCH_RESULT_LIMIT=3
BRAVE_SEARCH_API_KEY=
SERPAPI_API_KEY=
GOOGLE_SEARCH_API_KEY=
GOOGLE_SEARCH_ENGINE_ID=
```

검색 API 키는 Git에 커밋하지 않는다.

## 7. 도구 연결 작동 방식

전체 연결 흐름:

```text
React UI
  → API Gateway HTTP API
  → Lambda backend/src/app.mjs
  → backend/src/ragAdapter.mjs
  → backend/rag/lambdaHandler.mjs
  → internetSearchEvidence 또는 retrieveEvidence 또는 Bedrock Knowledge Bases
  → fallbackJudge 또는 Bedrock model
  → DynamoDB 저장
  → API Gateway 응답
  → React 결과 화면
```

상세 흐름:

1. 사용자가 React 화면에 발표자료 텍스트를 입력한다.
2. React가 `POST /analyze`로 `{ documentText, maxClaims, searchMode }`를 보낸다.
3. API Gateway가 요청을 Lambda로 전달한다.
4. Lambda가 입력을 검증하고 `analyzeDocument(input)`을 호출한다.
5. RAG 모듈이 claim 문장을 추출한다.
6. 각 claim에 대해 `searchMode: "internet"`이면 공식 출처 인터넷 검색을 먼저 시도하고, 실패하면 fallback evidence를 검색한다.
7. Bedrock 또는 fallback judge가 claim과 evidence를 비교해 라벨을 만든다.
8. Lambda가 결과를 공통 JSON 스키마로 정규화한다.
9. 결과를 DynamoDB에 저장한다.
10. 프론트엔드는 summary, label, reason, sources, evidence를 화면에 표시한다.
